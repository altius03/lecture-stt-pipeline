# 누락 강의 단건 복구 패널

## 배경

장소 이름으로 접수한 녹음이 후처리에서 빠지면 운영자가 작업 ID와 두 원전사 지문을 찾아 CLI로 재등록해야 했다. 검토 화면에서 과목을 직접 확정하고 같은 작업의 최종 전달까지 따라갈 수 있게 했다.

## 범위와 결정

- 검토 큐에서 후처리 제외·과목 미확정 작업을 찾고 녹음 시각과 분류 사유를 확인한다. 과목은 운영자가 직접 고르고, 확인 창에서는 한 건의 작업 번호·녹음명·과목을 다시 보여 준다.
- 확인 요청은 CLI의 재등록 함수를 호출한다. 이 화면에서 변경할 수 있는 대상은 미분류 작업으로 한정한다. 이미 같은 과목으로 확정된 요청은 기존 상태를 돌려주며 완료된 단계를 되돌리지 않는다.
- 목록과 상세 조회는 읽기 전용 SQLite 연결을 사용한다. Storage v2 기능을 켜지 않아도 접근할 수 있고, 대기열의 조회에는 생성기 실행이 필요하지 않다. 후처리가 꺼져 있으면 화면에 표시한다.
- 쓰기는 기존 웹 패널의 Host·Origin·운영자 권한 검사를 거친다. 확인 지문과 전체 과목 후보는 운영자의 복구 가능한 상세 화면에만 제공한다. 원전사 본문이나 로컬 파일 경로는 API 응답에 담지 않는다.

## 검증

- 임시 DB에서 원전사 파일 변경과 과목·학기 불일치, 산출물 예약, 다른 작업 상태, 반복 요청을 검증했다. HTTP 경로에서 잘못된 필드·범위, 읽기 전용 권한, 출처 거부, 안전한 오류 응답도 확인했다.
- React 테스트에서 과목 미선택·취소, 중복 클릭, 충돌 뒤 재선택, 페이지 이동, 완료 후 폴링 종료를 확인했다.
- 로컬 브라우저에 합성 녹음 두 건을 띄웠다. 한 건의 확인을 취소하자 SKIPPED가 유지됐고, 다시 확인하자 PENDING으로 바뀌었다. 격리된 후처리 워커를 두 번 실행한 뒤 해당 작업은 DELIVERED, 교정·요약·전달 시도는 각각 한 번이었다. 생성기를 모의 실행 파일로 대체하고 목적지 파일 세 개의 해시를 DB와 대조했다. 선택하지 않은 작업은 UNROUTED 상태를 유지했다.

## 운영에서 확인할 점

재등록은 후처리 대기열에 한 건을 넣는다. 진행 상태는 기존 워커가 갱신하며, 공유 환경에서는 운영자 권한과 활성 학기 설정이 필요하다. [운영 절차](../OPERATIONS.md#잘못-분류됐거나-입력-한도를-넘긴-강의-복구)
