# 운영 화면과 강의 복구 통합 배포

## 배경

운영 checkout에 작업 중심 홈·완료 후 품질 판정·Telegram 전용 정책이 적용되어 있었고 dev에는 누락 강의 복구와 프로세스·이력 보호가 추가됐다. 두 버전의 충돌을 별도 작업 공간에서 해결했다.

## 범위와 결정

- 현황 화면에서 오디오·전사·교정·요약 상태와 작업 상세를 본다. 확인 화면에는 완료 후 품질 판정과 누락 강의 단건 복구를 함께 제공한다. 확정 이력에서 교정·요약·전달 결과를 추적한다.
- 명확한 발화 누락·단절과 명시적 검토 보류는 작업을 검토 상태에 둔다. 일반 품질 경고는 완료 결과에 별도 확인 항목으로 남긴다. 품질 결정과 복구 요청은 운영자 권한을 확인한다.
- 알림 채널은 Telegram과 끄기를 지원한다. 이전 Discord 설정은 전송을 끄고, 채널 변경은 다음 작업에서 반영한다.
- 운영자 전환 전 기존 checkout, 설정, 서비스 등록, SQLite 백업과 바이너리 버전을 보존한다. DB와 녹음은 운영 경로를 유지한다. 격리 검증 → 접수 일시정지와 유휴 확인 → 버전 교체 → 서비스·HTTP·DB 검사 순으로 전환한다.

## 확인 사항

- 합성 자료로 작업 목록·품질 확인·후처리 복구·권한 거부를 검증한다. 실제 강의의 판정을 바꾸거나 의도치 않은 재전달을 유발하는 검사는 운영 DB에서 실행하지 않는다.
- Mac mini의 격리된 디렉터리에서 기존 캐시의 large-v3와 합성 한국어 음성으로 전사부터 과목 확정·후처리·전달을 확인했다. 별도 DB와 모의 생성기를 사용했으며 목적지 세 파일의 해시가 일치했다. 단건 재등록·워커를 반복해도 각 단계의 실행은 한 번이었다.
- 로컬 Python 904개, 웹 287개와 운영 빌드 및 Darwin 인수 검사 20회가 통과했다. 공유 경로의 조회와 SSH 운영자 경로의 변경 권한을 구분하고, Unix 소켓 프록시의 요청·출처 검사와 SSE 전달을 검사했다.
- PR의 Checks는 GitHub 실행 결과다. 운영 전환 여부는 별도 배포 확인 결과로 기록한다.
