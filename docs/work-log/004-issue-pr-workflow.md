# 이슈별 작업 기록과 PR 검증 절차

## 배경
날짜별 작업 기록은 변경 시점을 찾는 데 유용하다. 이슈에서 출발해 대안, 결정 이유, 검증 근거를 바로 찾을 수 있는 연결도 필요했다.

## 무엇을 할 것인가
Codex와 Claude가 공통 지침을 따르게 하고, 일반 이슈에서 작업 브랜치·작업 기록·PR 검증으로 이어지는 흐름을 제공한다.

## 대안과 트레이드오프
한 파일에 모든 기록을 누적하면 시작은 간단하지만 여러 작업이 같은 위치를 편집한다. 이슈별 파일은 날짜 인덱스 한 줄을 관리하는 비용으로 후속 PR의 결정을 같은 곳에서 추적할 수 있다.

## 결정 근거
이미 두 브랜치에 있는 AGENTS.md와 날짜별 기록을 활용한다. 기본 브랜치와 운영 코드의 이력이 갈라져 있어 각각의 기준 브랜치에서 절차 변경만 적용한다.

## 작업 내용
일반 이슈와 PR 양식, Claude의 공통 규칙 참조, 이슈별 작업 기록 양식을 추가했다. CI는 PR 파일 목록을 읽어 상세 기록 또는 예외 라벨을 확인한다.

## 결과
이슈에서 완료 조건을 정하고, PR에서 변경과 검증을 따라갈 수 있다. 기존 날짜별 기록은 인덱스로 이어 쓴다.

## 확인 사항
- 로컬에서 지침 링크, 템플릿, 작업 기록 검사 스크립트의 통과·실패·라벨 예외 등 10개 사례를 검증했다.
- GitHub CI 결과는 날짜 인덱스의 각 PR에서 확인한다. 이 변경에는 Mac mini 런타임 배포가 없다.

## 앞으로 할 일
개발·운영 브랜치 흐름을 정한 다음 이슈 생성 시 작업 브랜치를 자동으로 만들지 결정한다.
