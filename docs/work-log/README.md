# 이슈별 작업 기록

작업 이유와 결정 근거를 나중에 다시 찾을 수 있도록 GitHub 이슈 하나에 기록 파일 하나를 둔다. 날짜별 목록은 [기존 작업 기록](../WORKLOG.md)에서 관리한다.

1. 이슈 번호를 최소 세 자리로 채우고 영문 소문자와 하이픈으로 작업명을 붙인다. 예를 들어 이슈 #4의 기록은 [004-issue-pr-workflow.md](004-issue-pr-workflow.md)다.
2. 아래 양식을 새 파일에 복사한다. 같은 이슈가 여러 PR로 이어지면 기존 파일에 PR별 결과를 덧붙인다. 결정이 바뀌면 이전 결정과 변경 이유를 함께 남긴다.
3. 새 기록을 만들 때 날짜별 목록에 이슈와 상세 기록 링크를 한 줄 추가한다. PR이 열리면 그 항목에 PR 링크를 붙인다.
4. PR 본문에 이슈, 상세 기록, 수행한 검증을 연결한다. 개인 녹음 내용, 인증 정보, 비공개 필기 URL은 공개 작업 기록에서 제외한다.

## 복사할 양식

```markdown
# 작업명

## 배경
이 변경이 필요한 이유와 관찰한 문제.

## 무엇을 할 것인가
작업 범위와 완료 조건.

## 대안과 트레이드오프
검토한 방법과 각 방법의 비용.

## 결정 근거
선택한 방법과 선택 이유.

## 작업 내용
바꾼 파일과 동작.

## 결과
사용자가 확인할 수 있는 결과와 남은 제약.

## 확인 사항
실행한 명령과 결과. 로컬 테스트, GitHub CI, Mac mini 확인을 구분한다.

## 앞으로 할 일
남은 작업과 관련 이슈. 없으면 ‘없음’.
```

## PR 검사와 예외

`work-log check`는 PR에서 위 파일명 규칙에 맞는 상세 기록을 추가하거나 수정했는지 검사한다. 파일을 삭제하거나 날짜별 목록·이 안내문만 고치면 검사에 실패한다. 기록할 결정이 없는 오탈자 수정 등은 PR에 `skip-changelog` 라벨을 붙이고 사유를 적으면 통과한다. 기록의 내용과 검증 근거는 리뷰에서 확인한다.
