# main 운영 코드의 dev 통합

## 배경
기본 브랜치와 운영 코드의 이력이 갈라져 기본 브랜치의 문서와 실제 구현을 함께 따라가기 어려웠다.

## 무엇을 할 것인가
기본 브랜치에 운영 코드와 커밋 이력을 병합하고 기존 시스템 개요, 작업 규칙과 검증 기록을 보존한다.

## 대안과 트레이드오프
파일 복사나 스쿼시는 결과 파일을 가져올 수 있지만 기존 main 커밋을 dev의 조상으로 연결하지 못한다. 병합 커밋은 양쪽의 결정 이력을 추적할 수 있다.

## 결정 근거
main과 dev 양쪽의 작업을 이어갈 수 있도록 dev에서 통합 브랜치를 만들고 main을 병합한 뒤 같은 dev로 PR을 연다.

## 작업 내용
README와 아키텍처는 운영 구현을 기준으로 정리하고, 기본 브랜치의 시스템 개요 링크를 보존했다. 날짜 인덱스와 이전 작업 기록에는 양쪽 브랜치의 검증 결과를 모았다.

## 결과
dev에서 운영 코드와 기존 시스템 개요를 함께 읽을 수 있다. 운영 Mac 배포는 별도 작업이다.

## 확인 사항
- 병합 전 main과 비교해 문서 밖의 파일 차이가 없는지 검사했다. 제거했던 전용 통합의 파일과 참조가 없는지도 확인했다.
- CI 결과는 날짜 인덱스에 연결된 PR의 Checks에서 확인한다.

## 앞으로 할 일
이번 병합에 따른 추가 작업은 없다.
