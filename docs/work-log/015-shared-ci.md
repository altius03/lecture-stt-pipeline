# 로컬과 CI 검증 명령 공용화

## 배경과 완료 조건

CI에는 컨트롤러 종료 테스트의 이름과 반복 횟수가 있고, 로컬 문서에는 전체 검사를 재현할 명령이 흩어져 있었다. 같은 명령으로 양쪽에서 검사하고, PR에서 실패한 단계를 바로 찾을 수 있어야 한다.

## 대안과 결정 근거

작업 하나를 통째로 `make`에 맡기면 GitHub에서 테스트와 빌드 실패를 구별하기 어렵다. 각 검사에 타깃을 두고, 로컬에서 묶어 실행하는 타깃은 이들을 의존성으로 참조하게 했다.

Ubuntu는 러너의 Python을 쓰고, macOS 인수 검사는 체크아웃의 `.venv/bin/python`을 직접 실행한다. 인터프리터 준비는 각 환경에 맞추고 checkout, Python 버전·pip 캐시 설정과 요구 패키지 설치 명령을 공유한다.

## 작업 내용과 결과

- `make check-python`, `make check-controller`, `make check-web`을 README와 운영 문서에 연결했다. 의존성을 준비한 macOS에서는 `make check`로 모두 실행한다.
- GitHub에서는 기존 단계별로 같은 타깃을 호출한다. `controller-sigterm`은 두 종료 회귀 테스트를 race 모드에서 각각 10회 반복한다. `controller-darwin`은 macOS와 프로젝트 Python을 확인한 뒤 20회 연속 실행에서 총 100건을 검증한다.

## 확인 사항

- 로컬 Python 3.12.8에서 전체 866개 테스트, 컴파일, 컨트롤러 계약 125개가 통과했다.
- 기준 커밋 `3a9245b`와 워크플로를 비교했다. 3개 작업의 19단계에서 이름과 순서, 외부 액션·버전, 검사 대상과 옵션이 일치했다. 트리거·플랫폼·시간 제한과 작업 기록 검사도 확인했다.
- Python·Go·npm에 실패를 주입한 11개 호출이 모두 오류로 끝났고, 묶음 타깃은 첫 실패에서 멈췄다. macOS가 아닌 환경을 모사했을 때와 프로젝트 Python이 없을 때는 Darwin 검사가 Go 실행 전에 실패했다.
- GitHub CI 결과는 날짜 인덱스의 PR Checks에서 확인한다. 운영 Mac mini 확인·배포는 수행하지 않았다.
