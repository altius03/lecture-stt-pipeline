# 시스템·운영 이력 인수인계

## 배경
신규 담당자가 과거 대화를 읽지 않아도 시스템의 실행 경계와 최근 작업의 증거를 확인할 문서가 필요했다.

## 무엇을 할 것인가
두 기준 브랜치에서 같은 안내를 제공하고, 사용을 종료한 외부 후처리 도구의 전용 파일과 안내를 현재 트리에서 정리한다.

## 대안과 트레이드오프
README에 모든 이력을 합치면 설치 안내가 길어진다. 별도 문서에 이력과 사례를 모으고 README와 AGENTS.md에서 연결하면 독자가 필요한 깊이를 선택할 수 있다.

## 결정 근거
기본 브랜치와 운영 코드의 구성이 다르다. 주요 변경을 커밋·작업 기록과 연결하고, 최근 운영 사례에는 실제로 검증한 범위를 적는다.

## 작업 내용
공통 인수인계서, 읽기 전용 상태 조회, 다음 담당자에게 넘길 양식을 추가했다. 종료된 통합의 전용 코드·테스트·계획·운영 안내와 과거 작업 기록의 관련 항목을 정리했다. 공용 전사와 수동 교정, 현행 Codex 후처리는 별개의 경로로 유지한다.

## 결과
두 브랜치에서 같은 문서로 시작할 수 있다. 기본 워커의 기능과 별도 배치에서 수행한 제목 변경·자료 보완·게시의 경계를 확인할 수 있다.

## 확인 사항
- 로컬에서 변경 문서 링크, 인용한 커밋과 조회 열, 두 브랜치의 인수인계서 일치 여부와 삭제 대상의 경로·본문 잔존 여부를 확인했다. 예시 SQL 두 개는 운영 코드로 초기화한 임시 DB에서 실행했다.
- Python 테스트 805개 통과. 최초 실행에서 테스트 임시 루트가 체크아웃을 포함해 경로 거부 테스트 2개가 실패했다. 테스트 전용 TMPDIR을 체크아웃과 분리한 뒤 전체 스위트를 다시 실행했다.
- GitHub CI 결과는 날짜 인덱스에 연결한 각 PR의 Checks에서 확인한다. 운영 호스트 배포는 이 작업 범위에 포함되지 않는다.

## 앞으로 할 일
새 학기나 다음 대량 작업으로 처리 경계가 달라지면 해당 이슈 기록과 인수인계서의 사례를 함께 갱신한다.
