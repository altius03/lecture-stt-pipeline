# 원음 보존과 전사·후처리 복구 검증

## 배경

DB 경로가 비어 있는 상태에서 정리를 적용하거나 패널에서 오류 이력을 지우면 복구에 필요한 자료를 잃을 수 있었다. 빈 전사가 완료로 분류되고, 과목명을 바로잡은 녹음과 동기화 중 잠시 사라진 파일이 후처리에서 빠지는 사례도 있었다.

## 결정 근거

- 전달 완료 행도 중복 녹음 재사용의 근거다. 일반 정리 명령은 원음과 전사 세트를 보존하고, 그 원음의 SHA-256을 확인할 수 있는 작업용 WAV만 수명에 따라 정리한다.
- 과목 분류 변경은 운영자가 원전사 지문과 과목을 확인한 한 건에만 적용한다. 이미 교정·배달한 파일에는 기존 충돌 검사를 유지한다.
- 운영자 권한은 서버 측 인증 프록시에서 부여한다. 공유 접속에 토큰을 발급해 브라우저에 저장하는 절차는 필요하지 않다.
- 작은 실제 음성 테스트에서 faster-whisper 1.2.1이 신규 PyAV 19의 디코더 호출에 실패했다. 실제 PCM을 디코딩하는 회귀 테스트를 넣고 확인된 PyAV 18.1.1을 고정했다.

## 검증 증거

- 로컬 Python 3.12.8 unittest 845개, Node 22.23.5의 웹 패널 테스트 268개와 TypeScript/Vite 빌드가 통과했다. Go race와 vet, Darwin 파일시스템 인수 테스트 20회, Python 컴파일·셸 구문·plist 6개 검사도 통과했다. 설치 스크립트의 전체 흐름은 가짜 launchctl로 빌드 실패 전 등록 방지, 정상 등록과 상태 응답 실패를 검증했다.
- 잘린 UTF-8 TXT·JSON과 미완료 작업의 네 조합에서 중단 복구를 확인했다. 실제 Go와 Python 프로세스를 임시 SQLite에 연결한 뒤 작업 결과와 DB 무결성을 검사했다.
- 합성 음성으로 FFmpeg와 실제 Whisper tiny CPU 모델을 실행했다. 첫 녹음은 5구간과 TXT·JSON·quality를 남기고 완료했고, 같은 오디오는 기존 전사를 재사용했다. 4초 무음 파일은 0구간으로 검토 대상이 됐다.
- 한국어 합성 녹음 한 건을 기본 모델 large-v3 CPU/int8로 접수했다. 실제 Codex 후처리와 전달 워커를 거쳐 세 구간의 ID·시작·끝이 유지되고, 목적지의 교정 TXT·JSON과 요약 Markdown SHA-256 세 개가 DB와 일치했다. 다시 실행한 뒤에도 상태는 DELIVERED였고 SQLite 무결성 검사는 ok였다.
- 합성 한국어 한 문장으로 현재 Codex CLI에서 설정 예시 모델의 교정·요약을 실행했다. 구간 ID와 구조를 보존한 교정 JSON, 요약 Markdown을 확인했다.
- 로컬 브라우저에서 격리된 실제 패널의 SSE 연결, 처리 화면 이동, 정리 대상 0건의 확인 창과 취소, 390px 화면의 가로 스크롤 폭을 확인했다.
- Python·npm 의존성 감사를 다시 실행했다. 해당 환경과 잠금 파일에서 알려진 취약 항목은 0건이었다.
- 첫 hosted macOS 검사에서 SIGTERM 뒤 자식이 출력 파이프를 보유해 종료가 약 60초 걸렸다. 같은 경합을 로컬에서 재현하고, 컨트롤러가 만든 프로세스 그룹의 종료 처리와 상속 파이프 대기를 보완했다. 기존 2초 기준에서 40회 반복 통과했고 추가 회귀 검사에서도 자식 프로세스 회수와 대기 상한을 확인했다.
- 두 번째 hosted 검사는 그룹 ID가 남았다고만 보고해 그 순간의 생존 여부를 판별할 수 없었다. 후속 검사에서는 실행 상태와 이미 종료된 좀비를 구분하고 직접 자식의 회수, 생존 자손·열린 출력 파이프의 부재를 확인한다. 다른 그룹으로 이동한 자손은 운영체제에서 부모 관계와 생성 시각을 확인한 뒤 종료한다.
- 운영 Mac mini는 SSH 연결 시간 초과로 실동작을 확인하지 못했다. 모델·서비스·운영 DB 변경은 별도 배포 작업이다.

## PR 검수 후 보완

| 검수에서 재현한 문제 | 수정과 회귀 검사 |
|---|---|
| 정리가 동명 WAV를 워커 산출물로 잘못 식별 | 전용 임시 디렉터리, 열린 파일 디스크립터, 소유 확인용 하드링크로 실제 생성 파일을 확인한다. 합성 음성 전사 후 정상 정리와 별도 dry-run·apply를 실행해 동명 파일의 내용이 보존되는지 검증했다. 감시·오류 폴더 중첩, 파일 교체, 링크·잠금 미지원도 검사한다. |
| 품질 메타데이터가 없는 검토 작업의 복사본이 완료 처리 | 복사본의 품질 측정치와 별도로 원본 작업 ID로 검토 보류를 계승한다. 구버전 원본의 재사용, 알림, 중단 뒤 상태를 대조한다. |
| 무음 전사의 중단 복구 후 JSON·품질 파일·DB 판정 불일치 | 빈 본문 또는 빈 발화를 검출하면 구간 ID와 시간을 보존하며 현재 작업의 품질 기록을 맞춘다. 기존 전달에 경로나 해시가 고정됐으면 원본을 두고 복구본을 게시한다. 파일 게시 도중·DB 반영 전 중단, 재실행, 다른 녹음을 처리하면서 대기 건만 다시 복구하는 상시 워커를 검사한다. 패널과 수동 교정 스캔에서는 복구본을 별도 녹음으로 세지 않는다. |
| 기본 DB를 쓰는 패널에서 이력 정리 실패 | 패널 시작·미리보기·적용에서 같은 함수로 DB 경로를 해석한다. 기본 설정의 정상 적용과 미리보기 이후 DB 경로 변경·잘못된 값의 적용 거부를 확인했다. |
| 한 건의 재등록으로 원전사를 읽는 동안 전체 DB 쓰기 지연 | 원전사·학기 검증을 쓰기 트랜잭션 밖에서 수행하고 반영 직전 작업·큐 상태를 다시 대조한다. 파일 읽기 중 독립 연결의 커밋, 동시 재등록·전달, 지문과 학기 변경을 검증했다. |

보완 후 로컬 Python 866개, Node 22 웹 테스트 268개와 운영 빌드, Go 1.22.12 race·vet 및 Darwin 인수 검사 20회가 통과했다. 합성 녹음은 실제 Whisper tiny에서 5개 구간으로 완료됐고, 동일 오디오는 전사를 재사용했으며 무음은 검토 대상으로 남았다.

이전 CI 실패 두 건은 macOS의 SIGTERM 처리 경합에서 발생했다. 수정 후 GitHub에서 통과한 2초 종료 기준을 유지하며, 이후 PR에서도 SIGTERM·좀비 상태 회귀 테스트를 각각 10회씩 반복한다.

## 운영에서 확인할 점

공유 패널은 프록시의 사용자별 권한과 헤더 재작성 설정이 필요하다. 특대 전사의 입력 한도는 모델이 처리할 수 있는 범위에서 운영자가 조정한다. 배포 시 현재 워커 소유자, 활성 학기와 후처리 잠금, 정상 작업 한 건의 원음·전사 해시와 전달 결과를 확인한다. [운영 절차](../OPERATIONS.md)
